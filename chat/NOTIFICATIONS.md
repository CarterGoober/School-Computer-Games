# Notifications and quick DMs

This additive update preserves the existing accounts, messages, registration/admission gates, trusted grades and chat moderation. It applies after `public-registration.sql`; do not rerun the original schema. `notifications.sql` has been applied to the existing Supabase project.

## Behavior

- The bell shows the total unread eligible notifications, with a dropdown of the latest 100. DM messages, incoming friend requests, accepted requests and owner announcements create events in the same transaction as the underlying action. Message retries cannot create duplicates; reaction/edit updates do not create message notifications. No historical notifications are backfilled.
- Events store only actor/room/message references, type, timestamp and read state, not message bodies or school emails. RLS requires the active admitted recipient and current access. Blocks, mutes, deleted messages, friendship changes, grade changes and archived channels can suppress previously stored events. Clicking rechecks chat authorization and loads/highlights the exact message; friend requests open the matching Pending entry, and acceptance opens the consenting DM.
- Per-user settings, room pins/mutes, read state and notifications are stored in Supabase. Realtime subscriptions use recipient-filtered INSERT/UPDATE notification events and own settings/room updates. Revision changes invalidate other devices after friend/privacy changes without exposing private payloads. Resubscription, returning online and tab visibility refresh the snapshot; a 15-second visible-tab fallback remains if Realtime fails.
- Mark one or all notifications read; viewing a conversation marks its message notifications read through the existing authoritative read cursor. Category mutes and conversation mutes suppress notifications; blocked users do not notify. Sound defaults off and requires opt-in plus a browser gesture. Existing opt-in desktop notifications use generic text, never message previews. Closed-browser push is not implemented.
- Messages in the sidebar opens recent DMs, sorted by pins then latest activity, with initial avatars, usernames, unread counts and opt-in online status. Search, pin and mute controls are included. Friends has Pending/Online/All tabs, search/discovery, Accept/Decline, and quick DM entry. Presence still follows the existing refresh cadence.
- Announcements are now strictly owner-only, including if an older moderator permission record contains `announcements:true`. The old private management entrypoint was revoked from client execution to prevent bypassing that check. The moderator UI marks announcement permission owner-only. Other moderator permissions are preserved.
- Message retention continues as before. Message deletion removes/hides dependent notifications. Notification snapshots also remove that user's events older than 90 days; pins/preferences remain until account deletion. No private content is added to the Garage's offline cache.

## Verification

`test-notifications.sql` passed using the two existing real account/session contexts in a rollback-only transaction. Tested incoming/accepted request deduplication, retry-safe DM events, notification ownership and read persistence, cross-account read mutation denial, room pins/mutes, blocks, category settings, conversation read synchronization, owner-only announcements even with an old moderator grant, grade-restricted announcement delivery, deleted-message suppression, pending-account denial, RLS and client-forgery denial. No passwords, JWT minting, new accounts or permanent test messages were used.

The existing two-account chat authorization suite and public-registration suite also passed after the update: grades, private groups, consented DMs, replies/reactions/reporting, rate limits, moderation acceptance/revocation, bans and pending registration remain enforced. Production publication contains the three new tables, each with RLS and a recipient policy. Security advisors show no new warning category; the existing disabled leaked-password protection warning remains (see [Supabase guidance](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)).

`test-inbox-browser.cjs` passed at 1440px and 390px using clearly labeled **UI fixtures**, not real authentication. It covers bell/dropdown, exact message focus, read-all, duplicate-event alert suppression, DM search/pin/mute, friend tabs/acceptance, saved preference controls, silent defaults, reconnect status, logout cleanup, and horizontal overflow. Screenshots were inspected. Homepage/game links, public rules, public signup/pending UI, six delivery-state tests, 46 City Heist tests, and Garage wallet/shop tests passed.

## Remaining verification

Real notification WebSocket delivery, cross-device read/preference updates and audible sound have not been observed between independently authenticated browsers. The user's earlier passing live-chat report preceded this feature and is not counted as notification testing. The executor's direct public Supabase endpoint previously had DNS failures; database tests used the connected Supabase tool. No notification latency/load benchmark or closed-browser push claim is made.

For the live check: use the two approved accounts in separate browsers. Send/accept a friend request, send a DM while viewing another channel, post an owner announcement, and click each bell entry. Verify the other account cannot see private entries. Mark read on one device, refresh/reconnect another, toggle a category/room mute, pin a DM, block the sender, then send another message. Confirm no duplicate alert and that preference/read state persists. Enable sound deliberately before checking it. Do not share credentials or tokens.
