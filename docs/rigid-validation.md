# Rigid-body replacement

The old integrator assigned X/Z from heading, applied spring targets directly to height, clamped vertical speed and capped roll. It has been replaced by cannon-es 0.20.0, using a 1,500 kg compound rigid chassis, quaternion orientation, continuous 9.81 m/s² gravity, collision impulses and four spring/damper raycast wheels. Physics advances at exactly 1/120 second; fractional request time is retained in serialized state. Airborne motion is ballistic with small air damping. No height or upright-angle correction is used by the dynamics.

The same vendored engine/adapter runs on clients, the Node authority and the hosted Worker. Public checkpoint state includes quaternion, linear/angular velocities, steering and wheel travel/rotation. Client reconciliation corrects that state without resetting the vehicle on a delayed packet. JSON checkpoint continuation on flat ground matched uninterrupted simulation exactly in the test. Workers cache contexts by public vehicle identity, and terrain shapes use a bounded shared cache.

Physics terrain is streamed as nine nearby 16 m heightfield tiles, with 2 m sampling. Nearby rendered terrain now uses matching sampling. Static trees, rocks, buildings, rails, logs, signs and boundaries use fixed simplified colliders. Sign positions were corrected to the roadside using the road normal. The steepest added road hairpins exceeded physically climbable grades, previously masked by terrain following; these roads were regraded to a 26% centreline limit with broader earthworks. Actual terrain geometry and collision change together.

Verified: Earth-gravity free fall, analytical falling distance, retained horizontal/angular momentum, landing, braking/reverse, both steering directions, four-wheel slope contact, wall collisions, rollover/inversion, and driving at forest/ridge/beach locations. Browser tests dropped the real rendered wagon eight metres, observed airborne motion and landing, and checked bounded suspension travel at all three locations. Actual keyboard driving, orbit, zoom, multi-touch driving/camera, selected spawns, independent multiplayer clients, delayed snapshots, recovery/rejoin, Node persistence and offline loading were checked. Water tests crossed the fixed lake and river, confirmed sand/water resistance and bounded buoyancy. Both added ridge roads completed climbs and descents using physics-driven controls after the grading/sign fixes.

Warmed Node steps measured p95 around 0.11–0.24 ms; initial nearby collider preparation took about 5–14 ms and is performed while the selected spawn loads. These measurements are from the execution host, not physical Chromebook hardware. Full multiplayer load and physical Chromebook profiling remain unverified.

Approximations/limits: raycast tires are suspension mechanisms, not four separate wheel rigid bodies; static props use simplified primitive colliders. Cosmetic ripples, splashes and tracks are visual effects. Other explorers remain non-colliding, so vehicle-to-vehicle impact response is not implemented. Legacy tests that assumed forced ground contact or clamped roll are not evidence of rigid-body behavior; the current physical-control and rigid-body tests replace those assumptions.
